\section{Discussion}

Confluencia evaluates circRNA-specific dimensions absent from existing platforms (NetMHCpan, ADMETlab, Monolix) and implements a complete Design--Build--Test--Learn (DBTL) cycle for circRNA therapeutic optimization. The 5D evaluation and Go/No-Go decisions serve as the \emph{Design} stage, guiding candidate selection; RNACTM nucleotide modification and delivery configuration parameterize the \emph{Build} stage; PK simulation, immunogenicity prediction, and binding assays constitute the \emph{Test} stage; and the open training pipeline (\texttt{cf\_drug\_train()}, \texttt{cf\_epitope\_train()}) closes the loop by allowing models to be retrained on new experimental data (\emph{Learn}). No listed tool provides this closed-loop capability: existing platforms are single-pass predictors without a feedback mechanism from experimental outcomes back to model improvement. Under-constrained dimensions auto-downweight via $(1-u)^2$, reflecting data limitations.

Three lines of computational evidence support the platform: (1) immunogenicity scoring consistent with literature IFN data ($\rho{=}0.93$, $p{=}0.003$); (2) 5D decisions stable under $\pm$50\% weight perturbation; (3) gene signature target availability stratifies 3\,064 patients (log-rank $p{<}0.001$). We emphasize that all three lines are computational validations rather than independent wet-lab experiments; ongoing in-house experiments will provide the first independent circRNA benchmarks.

RNACTM pharmacokinetic predictions are consistent with published half-lives within 4.1\% for unmodified, m6A, and $\Psi$-modified circRNA \citep{wesselhoeft2018,chen2019}---though this constitutes consistency verification with the same literature that informed model parameters, not independent experimental validation. The productive expression window (40\,h) is within 17\% of the published ${\sim}48$\,h range after incorporating late-phase accelerated clearance. Endosomal escape (5.2\%) is at the upper bound of the 1--5\% literature range \citep{gilleron2013}. MHC binding prediction covers 153 MHC-I alleles (HLA-A/B/C) and 37 MHC-II alleles (DRB1/DQ/DP), enabling CD4$^+$ T-cell epitope screening alongside CD8$^+$.

The absence of circRNA-specific pharmacokinetic datasets motivated our uncertainty-adaptive design: RNACTM rate constants are derived from literature priors, and under-constrained dimensions auto-downweight via $(1-u)^2$. A central challenge for circRNA computational tools is that the field's data scarcity limits model performance---yet no existing tool addresses this scarcity itself. Confluencia breaks this chicken-and-egg problem through two mechanisms. First, the plugin system allows users to incorporate new algorithms (models, encoders, PK solvers, evaluation dimensions) as the field develops, so that methodological advances can be adopted without waiting for a new software release. Second, Confluencia Hub enables community data accumulation: the Hub operates in offline-first mode---users push a trained model bundle to local cache, pull it on another machine, and predict immediately, without requiring a central server. Federated model sharing lets users contribute trained models without exposing proprietary data---model bundles contain only fitted parameters and column metadata, never raw SMILES, sequences, or target values, and an optional \texttt{strip\_env\_medians} flag removes even aggregated statistics---while the optional data pool allows open datasets to grow over time under explicit licenses with anonymous upload as the default. Together, these mechanisms create a virtuous cycle---data scarcity limits Confluencia today, but each user's training and sharing makes the platform stronger for the next user, progressively alleviating the very scarcity that motivated its adaptive design.

We acknowledge that Confluencia's MHC binding prediction (AUC 0.74 on 288K samples without allele information; AUC 0.80 with allele-specific features) underperforms specialized tools such as NetMHCpan-4.1 (AUC 0.92--0.96). Per-allele performance is heterogeneous (Table~\ref{tab:allele_auc}): alleles with focused peptide repertoires reach NetMHCpan-level (HLA-A*33:01: 0.92, A*33:03: 0.95), but the most common alleles (HLA-A*02:01: 0.67, A*11:01: 0.61) remain challenging because their broad peptide diversity---binding peptides from hundreds of protein sources---makes the binding groove harder to model from generic sequence features alone. Allele-specific fine-tuning with concentrated per-allele training data is a viable future direction; in the interim, users who need state-of-the-art MHC binding for these challenging alleles can supplement Confluencia via the plugin system (\texttt{cf\_register\_model()} or \texttt{cf\_register\_encoder()}) to incorporate external tool outputs. Allele-aware features are recommended for datasets with $N{\geq}5000$; for small-sample settings ($N{<}300$), the 317-dim allele-agnostic mode avoids overfitting from high-dimensional MHC encoding. This gap reflects a deliberate trade-off: Confluencia is a multi-task platform providing PK simulation, immunogenicity prediction, dose optimization, and cross-modality evaluation---capabilities that NetMHCpan, ADMETlab, and Monolix each lack individually. The immunogenicity consistency check ($\rho{=}0.93$) uses the same literature that informed scoring rules and should be interpreted as consistency verification rather than independent validation; our ongoing wet-lab experiments will provide the first independent circRNA immunogenicity benchmark. Gene signature stratification achieves log-rank $p{<}0.001$ by capturing therapeutic target availability (high tertile: 57\% vs low: 20\% death rate), but the modest C-index (0.52) confirms that this score reflects target prevalence rather than intrinsic prognostic power.

Remaining limitations: (1) drug toxicity validation on $N{=}21$ samples yields weak correlations ($r{=}0.41$ for toxicity, $r{=}0.25$ for inflammation); accordingly, toxicity is assigned low weight in the default 5D composite and is flagged as exploratory; (2) circRNA ADMET maps classical endpoints to circRNA analogs rather than direct experimental toxicology data; (3) only half-life and immunogenicity among five circRNA functional dimensions have been benchmarked---translation potential, miRNA sponge, and RBP binding lack independent evaluation, and their under-constrained status is reflected via $(1-u)^2$ downweighting; (4) RNACTM rate constants are derived from literature ranges rather than fitted to circRNA PK datasets, and sensitivity analysis shows that $\pm$20\% variation in rate constants changes predicted half-life by ${\leq}$8.2\%. Wet-lab validation in our lab is underway to provide the first independent circRNA PK data.

To maximize reproducibility and lower adoption barriers, Confluencia provides three complementary interfaces sharing a single Python backend (\texttt{ConfluenciaBridge}): a graphical IDE for non-programmers, an R package for bioinformaticians who work primarily in R/ Bioconductor, and a VS~Code extension for developer-oriented workflows. This multi-interface design addresses a common limitation of computational biology tools---being implemented in one language but needed by communities that work in another---and ensures that reviewers can reproduce all results with a single \texttt{library(confluencia)} call in R or a command-palette entry in VS~Code, without writing Python. All interfaces expose the DBTL \emph{Learn} stage---model training---so that users can close the loop by retraining on their own datasets as circRNA experimental data grow, rather than being locked to pre-trained models. To further amplify the \emph{Learn} stage across the community, Confluencia Hub provides two sharing modalities in offline-first mode (no server required): (1)~federated model sharing, where users push a trained model bundle (\texttt{.joblib}) to local cache, pull it on another machine, and predict immediately, without exposing raw training data; (2)~an optional data pool, where users can contribute CSV datasets under explicit licenses (CC-BY-4.0, MIT, or proprietary) with anonymous upload as the default. A server deployment extends reach but is not required for core functionality. Beyond data sharing, Confluencia is designed as an extensible algorithm platform rather than a fixed tool: a plugin system allows users to register custom model types (\texttt{cf\_register\_model()}), sequence encoders (\texttt{cf\_register\_encoder()}), PK solvers (\texttt{cf\_register\_pk\_solver()}), and evaluation dimensions (\texttt{cf\_register\_dimension()})---so that the platform can evolve with the field rather than being frozen to the algorithms described in this paper. Evaluation weights are user-configurable (\texttt{cf\_set\_weights()}), allowing different therapeutic contexts to prioritize different dimensions. This dual design---community sharing for \emph{data} growth and plugin extensibility for \emph{algorithm} growth---ensures that Confluencia improves with use rather than becoming obsolete.
