\section{Discussion}

Confluencia provides the first integrated platform for circRNA drug evaluation---not because it outperforms specialized tools on individual tasks (NetMHCpan achieves AUC $>0.92$ on MHC-I binding \citep{reynisson2020}; ADMETlab covers $>50$ endpoints \citep{xiong2024}), but because no specialized tool exists for circRNA-specific pharmacokinetics, immunogenicity, or cross-module decision-making. The circRNA therapeutics field currently lacks the public PK datasets and clinical endpoint standards that enabled the development of tools like ADMETlab or NetMHCpan. In this data vacuum, Confluencia's design choices---literature-constrained ODE parameters, uncertainty-adaptive weighting, and physiological consistency floors---represent a principled approach to providing reasonable evaluations where data-driven alternatives are impossible.

The uncertainty-adaptive 5D evaluation is particularly suited to this context: dimensions without training data (e.g., clinical outcomes) automatically receive near-zero weight via the $(1-u)^2$ penalty, preventing the system from making overconfident predictions from under-constrained inputs. This is not a weakness but an appropriate response to data scarcity---the system communicates its limitations rather than hiding them.

Three limitations remain: (1) RNACTM protein expression duration is overestimated (97\,h vs 48\,h), requiring clearance model refinement; (2) ADMET QSAR lacks circRNA-specific toxicity data; (3) only MHC-I alleles are supported. These limitations are inherent to the circRNA domain's data scarcity, not to Confluencia's architecture. As clinical circRNA PK datasets emerge, the ODE parameters can transition from heuristic to data-fitted, and ADMET endpoints can expand accordingly---the architecture supports this evolution without redesign.
